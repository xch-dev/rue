# Rue

[![crate](https://img.shields.io/crates/v/rue-cli.svg)](https://crates.io/crates/rue-cli)
[![build](https://github.com/xch-dev/rue/actions/workflows/build.yml/badge.svg)](https://github.com/xch-dev/rue/actions/workflows/build.yml)
[![license](https://img.shields.io/badge/license-Apache--2.0-blue.svg)](LICENSE)

Rue is a statically typed programming language that compiles to [CLVM](https://chialisp.com/clvm) bytecode. It's designed as an alternative to [Chialisp](https://chialisp.com) for writing coin puzzles on the [Chia blockchain](https://chia.net).

[**Docs**](https://rue-lang.com) · [**Playground**](https://play.rue-lang.com) · [**Discord**](https://discord.gg/sagewallet)

```rs
fn main(public_key: PublicKey, conditions: List<Condition>) -> List<Condition> {
    let agg_sig = AggSigMe { public_key, message: tree_hash(conditions) };
    [agg_sig, ...conditions]
}
```

## Highlights

- **Type safe:** Structs, generics, type guards, and flow-sensitive narrowing catch entire classes of mistakes at compile time, before a puzzle ever touches the chain.
- **Optimized:** The compiler works hard to minimize the size and runtime cost of the generated bytecode.
- **Familiar:** A simplified, Rust-like syntax that feels more at home for most developers than Lisp.
- **Batteries included:** A standard library with conditions, tree hashing, currying, singletons, offers, and more.
- **Tooling:** A built-in test runner, formatter, CLVM debugger, and language server.

## Installation

Install the CLI from [crates.io](https://crates.io/crates/rue-cli):

```bash
cargo install rue-cli
```

See the [Installation](https://rue-lang.com/docs/installation) page for more options. If you just want to try the language, the [Playground](https://play.rue-lang.com) runs entirely in your browser.

## Quick Start

Create a new project:

```bash
rue init my-project
cd my-project
```

This creates a `Rue.toml` manifest and a `puzzles/main.rue` entrypoint:

```rs
fn main() -> String {
    "Hello, world!"
}
```

Compile it to CLVM:

```bash
$ rue build
(q . "Hello, world!")
```

## CLI

| Command                         | Description                                                            |
| ------------------------------- | ---------------------------------------------------------------------- |
| `rue init [path]`               | Create a new project with a `Rue.toml` manifest.                       |
| `rue build [file]`              | Compile the project (or a single file) and print the CLVM output.      |
| `rue test [file]`               | Run every `test fn` in the project (or a single file).                 |
| `rue fmt [paths...] [--check]`  | Format Rue source files, or check that they're already formatted.      |
| `rue debug <program> [solution]`| Run a CLVM program against a solution and print the result.            |
| `rue lints`                     | List every lint, along with its default level.                         |

Useful `build` flags:

- `--export <name>` - compile a specific exported function instead of `main`
- `--hex` - output serialized bytecode as hex
- `--hash` - output the tree hash of the compiled program
- `--debug` - include debug information such as assertion messages
- `--all` - compile every export in the project and write each one to a file (next to its source, or in `dist_dir` if set in `Rue.toml`)

## Lints

Warnings such as unused bindings or unnecessary casts are lints, which can be configured to be allowed, reported as warnings, or denied (which fails compilation). Run `rue lints` to see every lint and its default level.

Levels can be set in `Rue.toml`:

```toml
[lints]
unused_binding = "deny"
unnecessary_cast = "allow"
```

They can also be overridden for a single `build` or `test` with `-A`/`--allow`, `-W`/`--warn` and `-D`/`--deny`, which take precedence over `Rue.toml`:

```bash
rue build -D unused_binding -A unused_import
```

## Testing

Tests are just functions marked with `test`, and they live right alongside your code:

```rs
fn factorial(num: Int) -> Int {
    if num > 1 {
        num * factorial(num - 1)
    } else {
        1
    }
}

test fn factorial_works() {
    assert factorial(0) == 1;
    assert factorial(5) == 120;
}
```

```bash
rue test
```

## Examples

The [`examples`](examples) directory contains small programs like [FizzBuzz](examples/fizz_buzz.rue) and a [Brainf\*ck interpreter](examples/brainfck.rue), as well as real-world [puzzles](examples/puzzles) such as a [CAT](examples/puzzles/cat.rue), [singleton](examples/puzzles/singleton.rue), and [royalty split](examples/puzzles/royalty_split.rue).

> [!WARNING]
> The example puzzles have not been audited and are for educational purposes only.

## Contributing

Contributions are welcome! The project builds with a stable Rust toolchain (pinned in [`rust-toolchain.toml`](rust-toolchain.toml)).

```bash
# Run the full test suite
cargo test --workspace

# Regenerate the .yaml snapshots for tests/ and examples/ (optionally filtered by name)
cargo run -p rue-tests [filter]

# Lint and format
cargo clippy --workspace --all-targets
cargo fmt --all
cargo run -p rue-cli -- fmt 'examples/**/*.rue' 'tests/**/*.rue' 'crates/rue-compiler/src/std/**/*.rue'
```

Each `.rue` file in `tests` and `examples` has a matching `.yaml` snapshot with its compiled output, runtime cost, and test results. Review snapshot diffs carefully, since they show exactly how a change affects the generated bytecode.

To run the playground locally:

```bash
cd wasm && pnpm install && pnpm build
cd ../playground && pnpm install && pnpm dev
```
